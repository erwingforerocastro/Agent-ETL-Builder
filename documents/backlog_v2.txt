## Deferred assessment edge cases

- Inline source paths in messages; ambiguous or multiple candidate sources.
- Bounded sampling for large sources, assessment confidence, and background progress.
- Assessment timeout, cancellation mid-scan, and retry policy.
- Cache lookup/invalidation by `content_hash` and `schema_hash`.
- Re-checking the source hash after assessment and before confirmation/execution.
- User-edited drafts, multiple destination candidates, and explicit rejection of a draft.
- Destination format selection beyond the fixed v1 `save_csv` confirmation.
- Empty-source confirmation policy (allow or reject a vacuous load).
- Schema drift between assessment, confirmation, and execution.
- Assessment of PostgreSQL/new secret-bearing connections and one-time approval.
- Partial assessment artifact retention/cleanup and restart recovery.
- Assessment reports, HTML rendering, and optional narrative.
- Artifact path exposure policy if the API is exposed beyond the local workspace
  (currently assessment responses include the writer's absolute paths).

## Deferred transformation edge cases

The v1 transformation batch deliberately stays single-column and literal:

- OR/nested filter predicates; v1 composes multiple steps with AND.
- Regex, wildcard, or substring replacement; v1 is exact-match only.
- Multi-column imputation, forward/backward fill, and interpolation.
- Explicit date input formats, ambiguous formats, and mixed-timezone normalization.
- Column projection, rename, and drop modules.
- Filters that target multiple columns in one step; use multiple steps.
- Plan-time validation against the source schema; v1 checks columns and dtypes at execution.
- Explicit operation-kind metadata; v1 infers roles from pipeline inputs and side effects.

## Deferred profiling edge cases

These were intentionally moved out of the v1 profiler:

- Exact median/mode for very large full scans requiring spill/external sort.
- Bounded sampling, sample confidence, and approximate scope labels.
- Declared cross-column, duplicate-key, type, range, regex, domain, and unique-key rules.
- Per-column metric failure isolation and partial reports.
- Mixed numeric/string columns, mixed date formats, and naive/aware datetime unification.
- ISO 8601 duration output for date ranges.
- High-cardinality numeric mode display limits.
- Reloading or repairing per-chunk records; duplicate, missing, or corrupt record recovery.
- Assessment cache invalidation after source or schema changes.
- Numeric/date statistics for string columns that look like dates or numbers.

## Deferred operational edge cases

- Persistent checkpoints, active-run recovery, and crash resume.
- Approval timeout scheduling for runs that remain pending in the API.
- RunManager retention and eviction for long-running deployments.
- PostgreSQL connection pooling, exhausted pools, and read-only role grants.
- Configured database connections inside the registry sandbox.
- Rate limiting, stronger API authentication, and production secret management.
- Execution/transform JSONL logging, report HTML escaping, CSP, and external-CDN policy.
- Future non-PostgreSQL adapters and dashboards.

## Promotion rule

Before promoting an item, confirm it is needed by the current v1 user flow, define the smallest
acceptance test, and keep advanced policy or optional parameters out of the core path until the
flow exists.
